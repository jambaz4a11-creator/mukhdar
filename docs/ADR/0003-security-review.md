# ADR 0003: مراجعة الأمان قبل الإطلاق (T23): القرارات والمخاطر المقبولة

- **الحالة:** مقبول (2026-11-17). التقرير الكامل: [`docs/reviews/security-T23.md`](../reviews/security-T23.md) (1 حرج، 3 عالية، 7 متوسطة، 11 منخفضة).
- **القرار من:** صاحب المشروع (قرارات الجلستين E1 وE2). التنفيذ: migrations `20261130000001_security_t23.sql` و`20261201000001_security_t23_e2.sql`، والـ Edge Functions الإدارية، ولوحة الأدمن، وتطبيق الزبون، والسكربتات.
- **الاستبدال:** لا يستبدل قراراً سابقاً. يكمّل ADR 0001 (الدخول بالهاتف + PIN بلا SMS): المخاطر التي كشفتها المراجعة على ذلك التصميم (تخمين الـ PIN) عولجت هنا.

## السياق
PIN من 6 أرقام بلا قفل لكل حساب (Password Verification Hook لخطط Teams فقط) يعني أن حسابات القيمة العالية (أدمن وموظف) وحسابات الزبائن قابلة للتخمين عبر IPs متعددة، وأن حساباً مجانياً واحداً يستطيع حجز المخزون بطلبات وهمية. المراجعة (قراءة فقط) وجدت أيضاً ثغرتي نشر (CORS للدوال الإدارية، ودليل يضيف مرجع الإنتاج لقائمة التطوير).

## قرارات جلسة F (مراجعة E1/E2، قرارات المالك 2026-11-17، migration `20261202000001`)
| # | البند | القرار |
|---|---|---|
| F-H1 | إشعارات الأدمن/الموظف بجلسة aal1 أو خاملة | تسجيل الرمز وتسليم الإشعار يتطلبان **aal2** (نفس قاعدة `current_user_role`)؛ الرمز مربوط بالجلسة (`session_id`) ولا يُسلَّم إن انتهت أو خملت 12 ساعة. **عُدِّل 2026-11-24 (قرار المالك، SPEC-admin-push §4.1):** التسليم لم يعد يشترط جلسة حيّة؛ فحص الحساب وقت الإرسال وحذف فوري بالخروج الصريح/التخفيض/التعطيل/الحظر/الحذف. |

| F-M1 | التقييمات والموظف | الموظف يرى تقييمات آخر 7 أيام بغداد فقط؛ الأدمن الكل. |

| F-M3 | حد قيمة الطلب | 200,000 د.ع لكل طلب (مع التوصيل)، و50,000 للحساب الجديد حتى أول تسليم؛ يعدّلهما الأدمن (مُدقَّق). |
| F-M4 | اللوحة الخاملة | بعد 12 ساعة: خروج إلى صفحة الدخول برسالة عربية، لا قائمة فارغة. |

## المخاطر المقبولة (مع سببها)
1. **L1:** الوصول بالتوكن القديم لصفوف المستخدم نفسه ≤ ساعة بعد التعطيل (البيانات المحكومة بالدور تُقطع فوراً).
2. **لا CAPTCHA عند الإطلاق:** مخاطرة تخمين PIN الزبائن (قيمتها خصوصية حساب واحد) مقبولة مقابل بساطة التسجيل؛ يعالجها مؤشر التشغيل أعلاه. لا قفل لكل حساب (Teams فقط).
3. **تعداد الأرقام عبر `PHONE_TAKEN`:** مقبول (ADR 0001) تحت حدود 5/ساعة لكل رقم و20/ساعة لكل IP.
4. **L9:** مقبول (الاسترجاع عبر واتساب ← ضبط الأدمن بشروط M2).
5. **تعليق التقييم:** يبقى نصاً مجهولاً بعد حذف الحساب (مذكور بالسياسة).
6. **نسخ احتياطية:** بيانات الحساب المحذوف تبقى بالنسخ اليومية حتى 7 أيام.
7. **حساب الأدمن:** حساب أدمن لا يُضبط من اللوحة ولا من واتساب؛ استرجاعه من جهاز المالك فقط.
8. **تفاصيل غير مغطاة بالاختبار الآلي:** Playwright يغطي الترويسات و`?next=` والإخراج للخمول من صفحة الدخول؛ فحص انتهاء 12 ساعة نفسه مغطى بـ pgTAP (`30_security_e2.sql`) وDeno لا بساعة حقيقية.

## ما لم يُنفَّذ (يدوي، بموافقة المالك، موثق بـ RUNBOOK §17.5)
إعدادات لوحات Supabase/Vercel/GitHub/EAS للإنتاج (2FA، Dependabot، Realtime، مفاتيح API الجديدة، حدود المعدل، Turnstile عند العلامة). لم يُغيَّر شيء منها بهذه الجلسة.
