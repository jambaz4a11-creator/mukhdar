# 25: الرئيسية (مؤشرات اليوم)

**الهدف:** SPEC-admin §2.0، وSPEC-backend §12.3 (`dashboard_today`). قرارات المالك 2026-11-15.
**يعتمد على:** 17 (مكوّن جدول الطلبات)، 18 (كلفة الهدر وحد النقص)، 20 (تعريفات التقارير)، وشاشة "الرئيسية" بالتصميم المعتمد.

## الخطوات
- migration:
  - `dashboard_today() → jsonb` (موظف وأدمن، بتوقيت بغداد): اليوم حتى الآن وأمس حتى نفس الدقيقة للمسلّمة (`delivered_at`) والملغاة (`cancelled_at`) والواردة (`created_at`)؛ المفتوحة الآن بكل حالة؛ عدد المنتجات تحت حد النقص؛ وللأدمن فقط: المبيعات (بدون الأجرة)، متوسط الطلب، كلفة هدر اليوم، صافي ربح اليوم وأمس كاملاً. للموظف حقول المال `null`.
  - فهرسان جزئيان: `orders(delivered_at) where status = 'delivered'`، `orders(cancelled_at) where status = 'cancelled'`.
  - التطبيق على mukhdar-dev بموافقة صاحب المشروع.
- الصفحة `/`:
  - بطاقات حسب SPEC-admin §2.0، مع نسبة التغيّر وسهم ("—" عند غياب أمس).
  - طلبات اليوم بمكوّن جدول T17 مع رابط للطلبات.
  - Realtime: أي طلب جديد أو تغيير حالة يعيد `dashboard_today()` (debounce ثانيتين).
  - قواعد العرض: لا قص للأرقام، حاوية حتى 1600px، شبكة `auto-fit`.
  - الموظف: لا بطاقة مال ولا رقم بالدينار.

## القبول
- على بيانات seed بوقت ثابت: الأرقام تطابق استعلامات التحقق اليدوية (ومنها أمس حتى نفس الدقيقة، لا أمس كاملاً).
- طلب يُسلَّم 23:59 بغداد يُحسب لذلك اليوم لا لليوم التالي.
- رقم 123,456,750 د.ع يظهر كاملاً ببطاقة عرضها 180px وعلى شاشة 1920px.
- الموظف: `dashboard_today()` ترجع المال `null`، والصفحة بلا "د.ع".
- الصفحة تفتح < 1 ثانية على بيانات seed.

## الاختبارات
- pgTAP: `dashboard_today` (حدود اليوم وأمس حتى نفس الوقت بتوقيت بغداد، حذف المال للموظف، منع الزبون والسائق).
- وحدة: نسبة التغيّر (أمس صفر، نقصان، زيادة)، تنسيق الأرقام الكبيرة.
- Playwright: أدمن يرى كل البطاقات؛ موظف بلا مبالغ؛ تسليم طلب يحدّث البطاقات وجدول اليوم.
