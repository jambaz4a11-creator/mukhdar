# 42: تطبيق السائق: الكاش منذ آخر تسليم وسجل التسليمات ⬜

**الهدف:** SPEC-cash §5 (يحل محل SPEC-driver §2.9، U8). "الكاش اللي بيدك" من `driver_cash_summary()` منذ آخر تسليم (لا منذ منتصف الليل)، قائمة الطلبات بذمته، شاشة "سجل التسليمات"، إشعار `cash_handover`، ورسالة `CASH_OUTSTANDING` بحذف الحساب. الأصلي والـ PWA.
**يعتمد على:** 40.
**النموذج المقترح:** Sonnet (تعديلات شاشات بنمط T32).
**على dev:** لا شيء (PWA السائق تُبنى على Cloudflare Pages بعد الدمج؛ الـ APK مع T33). لا migration ولا Edge Function.
**الحجم:** M.

## الخطوات
1. `apps/driver/src/features/cash/`: `summary` (K10) و`history` (K11، keyset 20) + اختبارات.
2. `(tabs)/today.tsx`: بطاقة الكاش من الدالة (و"المطلوب تسليمه للمحل" + "أجرة التوصيل إلك، ما تنحسب" إن كان `includes_delivery_fee = false`)، "من آخر تسليم …" أو "ما سلّمت كاش بعد"، قائمة الطلبات بذمته (RLS الموجودة، حد 200، عرض فقط)، الملاحظة الجديدة، ورابط "سجل التسليمات".
3. شاشة `cash/history.tsx`: الوقت، المستلم، المطلوب إن اختلف، شارة نقص/زيادة، الملاحظة (نص صرف)، اسم المستلم، "تعدّل".
4. `routeForNotification` + `public/sw.js`: `cash_handover` ← `/(tabs)/today` مع تحديث؛ `sw-parity.test.ts`.
5. حذف الحساب: `CASH_OUTSTANDING` ← "عندك كاش ما سلّمته للمحل (X د.ع). سلّمه أولاً".
6. التحديث عند فتح الشاشة، الرجوع للتطبيق، سحب للتحديث، ووصول الإشعار. SPEC-driver §2.9.

## القبول
- البطاقة من الدالة لا من مجموع القائمة، وتتصفّر بعد التسليم لا منتصف الليل.
- السجل يعرض الشارات والتصحيح، وصفحات بالتمرير.
- نقر إشعار `cash_handover` (أصلي وويب) يفتح سجل اليوم ويحدّثه.
- مسار التوصيل وباقي الشاشات بلا تغيير.

## الاختبارات
- Jest/RNTL (`apps/driver`، `--maxWorkers=2`): البطاقة، الحالة الفارغة، السجل، التوجيه، رسالة الحذف، `sw-parity`.
- Playwright PWA الحالي يمر (CI `web-builds`).
