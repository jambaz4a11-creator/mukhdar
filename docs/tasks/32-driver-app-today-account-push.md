# 32: تطبيق السائق: سجل اليوم وحسابي والإشعارات ⬜

**الهدف:** SPEC-driver §2.9–§2.11.
**يعتمد على:** 31.
**النموذج المقترح:** Sonnet.
**على dev:** لا migration ولا Edge Function. **يحتاج موافقة صاحب المشروع** على: إنشاء مشروع EAS لـ `com.mukhdar.driver`، وتطبيق Android ثانٍ بـ Firebase (FCM، ملف `google-services.json` كمتغير ملف بـ EAS لا بـ git)، وبناء **development build** واحد للفحص (Expo Go لا يستلم الإشعارات).
**الحجم:** M.

## الخطوات
1. `packages/shared`: `baghdadDayRange(now) → {from, to}` (UTC+3 ثابت) مع اختبارات الحدود.
2. شاشة اليوم (تصميم Today): طلباتي المسلّمة ضمن اليوم (حد 200، الأحدث أولاً)، "الكاش اللي بيدك" = Σ `total_iqd`، "توصيلات اليوم" = العدد، القائمة (`#N · بلوك · بناية`، الوقت، المبلغ)، ملاحظة التصفير، تحديث عند الفتح والرجوع.
3. شاشة حسابي (تصميم Account): الاسم والرقم و"سائق"؛ "تغيير الرمز السري" (الحالي + الجديد + التأكيد، مسار ADR 0001)؛ "اتصل بالمحل" و"واتساب المحل"؛ "تسجيل الخروج" (حذف صف `push_tokens` للجهاز ← إلغاء Realtime ← `signOut`)؛ **"حذف الحساب"** بتأكيد (`delete-account`، `ACTIVE_ORDER` برسالة).
4. `src/lib/push.ts`: قناة `orders` (أهمية عالية، صوت)؛ الإذن بعد أول دخول؛ `register_push_token(token, platform, 'expo')` عند كل تشغيل بجلسة سائق فعّالة وبعد الدخول وتغيير الرمز المؤقت؛ شريط "الإشعارات مطفية" برابط الإعدادات.
5. فتح الإشعار حسب `data.type` (`new_order`، `ready`، `assigned`، `unassigned`، `cancelled`، `driver_request_approved`) بما فيها التطبيق مغلق تماماً.
6. RUNBOOK: إعداد EAS/Firebase لتطبيق السائق والمتغيرات.

## القبول
- مجموع اليوم يطابق استعلام SQL يدوي؛ طلب سُلّم 23:59 بغداد يُحسب لذلك اليوم و00:01 لليوم التالي.
- تغيير الرمز: القديم يفشل والجديد ينجح وباقي الأجهزة تخرج.
- الخروج يحذف رمز الجهاز قبل `signOut` (لا إشعارات بعده).
- حذف الحساب بطلب غير منتهٍ مرفوض برسالة؛ بدونه ينجح ويرجع للدخول.
- على development build: "جاهز" من اللوحة يصل إشعاراً للسائق ويفتح الجاهزة؛ الموافقة على طلب تسجيل تصل إشعاراً لجهاز بلا حساب.

## الاختبارات
- وحدة: `baghdadDayRange` (حدود منتصف الليل، 23:59/00:01)، مجموع اليوم.
- Jest/RNTL: تغيير الرمز (عدم التطابق، الجديد = الحالي، `validatePin`)؛ ترتيب الخروج (حذف الرمز قبل `signOut`)؛ رسالة `ACTIVE_ORDER`؛ توجيه الإشعار لكل `type`.
- فحص يدوي على development build: الإشعارات (مفتوح، بالخلفية، مغلق).
