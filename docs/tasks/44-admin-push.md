# 44: تنبيهات لوحة الأدمن: Web Push + صوت + PWA ⬜

> المواصفة: [SPEC-admin-push](../SPEC-admin-push.md). مهمة طويلة بغياب المالك (2026-11-24): القرارات غير المحددة افتراضات بالـ SPEC §9، والأسئلة §10.

**الهدف:** المالك والموظفون يعرفون فوراً بطلب جديد، وطلب سائق ينتظر الموافقة (أدمن فقط)، وطلب ألغاه الزبون، حتى واللوحة مقفولة.
**يعتمد على:** T35–T38 (المرسِل والاشتراكات)، T23 (aal2 وخمول 12 ساعة).
**النموذج:** Opus.
**على dev (موافقة مسبقة بالمهمة):** migration واحدة، نشر `push-config` (جديدة) و`push-dispatch`. لا أسرار، لا Cloudflare، لا إنتاج.
**الحجم:** M.

## الأجزاء (فرع وPR لكل جزء)
1. **docs:** SPEC-admin-push + هذا الملف + صف الجدول.
2. **backend:** migration `20261216000001_t44_admin_push.sql` (نص الطلب الجديد بلا عنوان؛ إشعار `customer_cancelled` للوحة عند إلغاء الزبون)، pgTAP `42_admin_push.sql` بالأدوار الحقيقية، دالة `push-config` + اختبارات Deno، `customer_cancelled` عالية الأولوية بـ `push-dispatch`، `push-config` بفحص CORS الحي. بعد الدمج: dry-run ← `db push --remote` ← `functions deploy` على dev.
3. **admin client:** manifest + أيقونات + `sw.js` + استثناؤها من الـ proxy + `worker-src`، لوحة "تنبيهات هذا الجهاز" (تشغيل/إطفاء لكل جهاز، الصوت)، إعادة التسجيل الصامتة، حذف الاشتراك عند الخروج، شريط "فعّل الصوت"، `(N)` بعنوان التبويب، توجيه النقر؛ vitest وPlaywright؛ الفحص الدخاني الحي للوحة.

## الاختبارات
- pgTAP بدور الزبون والموظف والأدمن الحقيقي (JWT)، Deno للدالة، vitest، Playwright (Chromium)، الفحص الدخاني الحي بعد كل دمج.

## معايير القبول
- لا هاتف ولا عنوان ولا نص حر بأي إشعار للوحة (اختبار آلي).
- الموظف لا يستلم طلبات السواق ولا نقص المخزون.
- النقر يفتح الطلب أو صفحة طلبات السواق.
- اللوحة قابلة للتثبيت (manifest + SW) والإشعار يصل على iPhone من الشاشة الرئيسية (فحص المالك اليدوي).
- CI الأربع خضراء بعد كل دمج والفحص الدخاني الحي ناجح.
