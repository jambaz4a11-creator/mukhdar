# 22: اختبار الحمل (k6)

**الهدف:** التحقق من SPEC-backend §9 بأرقام.

## الخطوات
- مشروع Supabase **staging** بخطة Pro وبنفس حجم Compute الإنتاجي. `seed:demo --scale=load`.
- `load/` بالمستودع: سكربتات k6 للسيناريوهات الثلاثة (ذروة الطلبات، التصفح، التنافس).
- الدخول: توكنات مولّدة مسبقاً للمستخدمين التجريبيين (لا OTP أثناء الاختبار).
- السائق يُحاكى باستدعاء نفس دوال العقد (`available_orders`، `accept_order`، `set_order_status`) بتوكنات سائقين تجريبيين؛ لا يعتمد على تطبيق السائق الخارجي (T21).
- تسجيل النتائج بـ `docs/ADR/0002-load-test.md`: p50/p95/p99، الأخطاء، استخدام CPU والاتصالات من لوحة Supabase.
- `EXPLAIN ANALYZE` لأثقل 5 استعلامات بعد الاختبار (من `pg_stat_statements`).

## القبول
- p95 `place_order` < 500ms، p95 الكتالوج < 300ms، أخطاء غير متوقعة < 0.5%.
- سيناريو التنافس: عدد الطلبات الناجحة = الرصيد بالضبط، صفر deadlocks.
- إن لم تتحقق العتبات: إصلاح (فهرس، استعلام، أو رفع Compute) وإعادة.

## الاختبارات
- سكربتات k6 نفسها بـ `thresholds` تفشل تلقائياً عند تجاوز الحدود.
