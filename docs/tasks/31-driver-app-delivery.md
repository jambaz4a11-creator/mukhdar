# 31: تطبيق السائق: الطلبات الجاهزة وطلباتي والتفاصيل ⬜

**الهدف:** SPEC-driver §2.6–§2.8: دورة التوصيل كاملة بالتطبيق، بدوال السائق الموجودة.
**يعتمد على:** 30، ومراجعة R1 منجزة.
**النموذج المقترح:** Sonnet (شاشات على API موجود ومختبر؛ العقد بـ DRIVER-API §3–§5).
**على dev:** لا migration ولا Edge Function.
**الحجم:** M–L (ثلاث شاشات + منطق مشترك).

## الخطوات
1. `features/orders/available.ts`: `available_orders(20)`، تحديث (سحب، 30 ثانية والشاشة ظاهرة، رجوع للتطبيق)؛ `accept.ts`: `accept_order` و`ORDER_NOT_AVAILABLE` ← "قبله سائق ثاني" ثم حذف بالتحديث؛ `NOT_ALLOWED` ← إعادة فحص الحارس.
2. شاشة الجاهزة (تصميم Main): البطاقة (الرقم، "جاهز من N دقيقة"، بلوك + بناية فقط، "N منتجات" من `line_count`، الكاش بـ `formatIqd`، "قبول الطلب")، الشارة بالعدد، الحالة الفارغة.
3. `features/orders/mine.ts`: الاستعلام (DRIVER-API §4) + Realtime بفلتر `driver_id=eq.<me>` + إعادة جلب عند الرجوع وإعادة الاتصال وكل 30 ثانية؛ اختفاء طلب أو `cancelled` ← إزالته برسالة.
4. شاشة طلباتي (تصميم MyOrders): الحالة بالتسميات ("بالطريق"، "مقبول، بعده بالمحل"، "بانتظار التحضير")، العنوان بـ `formatAddress`، الاسم، الكاش.
5. `features/orders/transitions.ts` (`nextAction`، SPEC-driver §6) وشاشة التفاصيل (تصميم OrderDetail): مربعات العنوان (`G` للصفر، إخفاء المفقود، زبون محذوف)، الزبون (اتصال `tel:`، واتساب `wa.me/964…`)، المنتجات بـ `formatQuantity`، ملاحظة الزبون، الكاش، الزر الثابت حسب الحالة، تأكيد مزدوج للتسليم يعرض المبلغ، أخطاء `INVALID_TRANSITION`/`NOT_ALLOWED`، "مشكلة بالطلب؟ اتصل بالمحل".
6. صفوف `order_status_history` غير الحالات (`driver_accepted`...) لا تُعرض كتغيير حالة إن عُرض السجل.

## القبول
- البطاقة قبل القبول بلا اسم ولا هاتف ولا طابق ولا شقة.
- سائقان يقبلان نفس الطلب: واحد ينجح، الثاني يرى "قبله سائق ثاني".
- `ready` ← "بالطريق" ← "تم التوصيل" (تأكيد ثانٍ) يغيّر الحالة بقاعدة البيانات، والزبون يستلم إشعاره (الموجود).
- تغيير الحالة أو النقل لسائق آخر من اللوحة يظهر بالتطبيق خلال 30 ثانية (Realtime أو الاستطلاع).
- العنوان: `بلوك A3 · بناية 12 · الطابق G · شقة 4`؛ عنوان قديم بلا طابق يُعرض بلا مربع الطابق.

## الاختبارات
- Jest/RNTL: البطاقة بلا بيانات الزبون؛ "قبله سائق ثاني"؛ `nextAction` لكل حالة؛ التأكيد المزدوج؛ مربعات العنوان (0 ← G، مفقود، محذوف)؛ رابط واتساب (`07…` ← `9647…`)؛ إزالة طلب ملغى أو مختفٍ.
- التزامن الموجود بـ CI (`db:concurrency`: 8 سائقين على طلب واحد) يبقى أخضر.
- فحص يدوي على dev: دورة طلب كاملة بحساب سائق العرض وطلب من تطبيق الزبون.
