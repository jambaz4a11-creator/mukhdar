# 20: التقارير

**الهدف:** SPEC-admin §2.5، وSPEC-backend §12.3 (التقارير). تعريف المبيعات وصافي الربح: SPEC-backend §2 (قرارات 2026-11-15).

## الخطوات
- اختيار المدى، بطاقات المؤشرات من `daily_stats` (ومنها كلفة الهدر وخسارة التسويات وصافي الربح من T18)، رسم يومي للمبيعات وصافي الربح.
- دوال SQL جديدة (migration)، أدمن فقط، بتوقيت بغداد، مدى أقصى 366 يوماً: `report_top_products(from, to, limit)`، `report_drivers(from, to)`، `report_waste(from, to)`، `report_orders_placed(from, to)`.
- تقرير الهدر: جدول لكل منتج (الكمية بالكيلو لنص الكيلو وبالوحدة للباقي عبر `formatAdminQuantity`، SPEC-admin §2.9؛ الكلفة) مرتّب بالكلفة. أكثر المنتجات مبيعاً بنفس القاعدة. الدوال ترجع وحدات البيع والتحويل بالواجهة.
- متوسط التقييم وآخر 20 تعليقاً.
- تصدير CSV (المؤشرات اليومية وتقرير الهدر): الكمية بالكيلو أو الوحدة مع عمود الوحدة.

## القبول
- أرقام التقرير على بيانات seed تطابق استعلامات التحقق اليدوية، ومنها: صافي الربح = الربح الإجمالي − الهدر − التسويات السالبة؛ المبيعات بدون الأجرة وبتاريخ `delivered_at`.
- صفحة التقارير لمدى شهر تفتح < 1 ثانية على بيانات seed.
- هدر 7 أنصاف كيلو من منتج يظهر "3.5 كيلو" بالتقرير وبالـ CSV؛ هدر 3 باقات يظهر "3 باقة".

## الاختبارات
- pgTAP للدوال الأربع (أرقام، حدود اليوم بتوقيت بغداد، منع غير الأدمن ومنهم الموظف).
- Playwright: تغيير المدى يحدّث البطاقات؛ التصدير ينزل ملفاً.
