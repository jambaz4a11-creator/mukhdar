# 41: اللوحة: تسليم الكاش وإعداد الأجرة ⬜

**الهدف:** SPEC-cash §4. صفحة `/cash` (الأرصدة، نافذة الاستلام، السجل، التصحيح)، قسم "الكاش والسواق" بالتقارير، وإعداد الأجرة (K19) بـ `/settings` بشرح عربي واضح. كل الأرقام من دوال T40؛ الواجهة تعرض فقط.
**يعتمد على:** 40.
**النموذج المقترح:** Sonnet (واجهة فوق دوال جاهزة، بنمط "طلبات السواق" و"التقارير").
**على dev:** لا شيء (Cloudflare ينشر اللوحة بعد الدمج بـ `main` تلقائياً). لا migration ولا Edge Function.
**الحجم:** L.

## الخطوات
1. `apps/admin/src/features/cash/`: دوال صرفة + اختبارات: `cashDifference`، تحقق المبلغ (مضاعف 250، أرقام عربية/لاتينية، الحد)، تحويل الأخطاء (`CASH_BALANCE_CHANGED` بقراءة `detail`)، قاعدة إعادة استخدام مفتاح منع التكرار، نص "شامل/بدون أجرة التوصيل".
2. `access.ts`: `/cash` للأدمن والموظف؛ القائمة الجانبية بعد "الطلبات".
3. صفحة `/cash`: الرأس (الكاش عند السواق الآن)، تبويب الأرصدة (K4)، نافذة الاستلام (K5 + K6، حقل فارغ + "نفس المبلغ"، فرق حي، ملاحظة إلزامية مع الفرق)، تبويب السجل (K7، keyset 50، ملاحظة الموظف 7 أيام)، "تصحيح" للأدمن (K12). تحديث عند التركيز وكل 30 ثانية وبعد كل عملية.
4. التقارير: قسم "الكاش والسواق" (K13) + CSV.
5. `/settings`: قسم "أجرة التوصيل وتسليم الكاش" بخيارين والشرح والتنبيه (SPEC-cash §4) ← `update_app_settings({cash_handover_includes_delivery_fee})`.
6. النصوص العربية بملفات i18n؛ المبالغ بـ `formatIqd`؛ SPEC-admin §2.11 (الصفحة) و§2.5 (التقارير) و§2.10 (الإعداد).

## القبول
- موظف: يرى الأرصدة، يسجّل تسليماً مطابقاً ← الرصيد 0؛ نقص بلا ملاحظة ← الزر معطّل؛ بملاحظة ← يظهر بالسجل بشارة "نقص"؛ لا يرى "تصحيح" ولا قسم التقارير ولا الإعداد.
- `CASH_BALANCE_CHANGED` يحدّث المطلوب ويمسح المبلغ المكتوب (لا نقص وهمي).
- أدمن: تصحيح، قسم التقارير، وتغيير إعداد الأجرة يظهر بالنافذة ("بدون أجرة التوصيل") والرصيد يتغير.
- زبون ← "غير مصرح".
