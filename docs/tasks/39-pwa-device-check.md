# 39: فحص PWA والإشعارات على أجهزة حقيقية (W7) ⬜

**الهدف:** SPEC-webpush §10 (معايير النجاح). فحص يدوي موثَّق على آيفون 11 (iOS 16.4+، متوفر، قرار المالك Q4) وعلى Android Chrome.
**يعتمد على:** 38.
**النموذج المقترح:** Sonnet (فحص موجَّه وتقرير).
**على dev:** لا migration ولا نشر جديد (بيئة T36–T38 جاهزة). لا قيم إنتاج.
**الحجم:** S.

## الخطوات
1. التحقق قبل البدء: CI أخضر على `main`، `pnpm sb migration list --remote` بلا اختلاف، `push-dispatch` منشورة بأسرار VAPID، متغير `EXPO_PUBLIC_VAPID_PUBLIC_KEY` بمشروعي Pages.
2. **آيفون:** Safari (تبويب) ← بوابة التثبيت تحجب التسجيل ← إضافة إلى الشاشة الرئيسية ← تسجيل سائق **داخل الـ PWA** ← الموافقة من اللوحة (polling 30 ثانية) ← اختيار الرمز ← الدخول ← بطاقة الإشعارات ← المنح.
3. **إشعارات (آيفون وAndroid Chrome):** من اللوحة حوّل طلباً إلى `ready` ← يصل إشعار والتطبيق مفتوح/بالخلفية/مقفول تماماً ← النقر يفتح الطلب ← قبول ← "بالطريق" ← "تم التوصيل" ← سجل اليوم. **زمن الوصول** يُسجَّل لكل حالة.
4. **الزبون PWA** على الآيفون: طلب ← إذن بعد أول طلب ← إشعارات الحالات.
5. **الخروج:** من حسابي، ومن شاشة "ماكو اتصال" (وضع الطيران) ← لا إشعار بعدها ← صف `push_tokens` محذوف (أو يُحذف بعد العودة للشبكة).
6. **الإخلاء/إعادة التثبيت:** حذف التطبيق من الشاشة الرئيسية ثم تثبيته: الجلسة تُفقد ويُطلب الدخول، وبطاقة الإذن تعود؛ طلب تسجيل بلا سر جهاز يعطي الرسالة الصحيحة.
7. RTL والمناطق الآمنة (الجزيرة/الشريط السفلي) وأزرار الاتصال والواتساب على الآيفون.
8. التقرير `docs/reviews/pwa-webpush-W7.md`: الأجهزة وإصدارات iOS/Android، كل بند ناجح/فاشل مع لقطة وزمن، المشاكل المفتوحة؛ و`docs/PREVIEW.md` (تثبيت السائق والزبون على آيفون).

## القبول
- كل معايير SPEC-webpush §10 ناجحة على الآيفون، أو كل فشل له مهمة إصلاح مكتوبة (القاعدة 7: لا تجاوز).
- التقرير مدموج بـ `main`.
