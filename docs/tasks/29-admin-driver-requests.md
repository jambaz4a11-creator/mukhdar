# 29: لوحة الأدمن: "طلبات السواق" ⬜

**الهدف:** SPEC-driver §5 (تُنقل لـ SPEC-admin §2.10 بهذه المهمة).
**يعتمد على:** 27 (الدوال). مستقلة عن 28 (يمكن تنفيذها قبلها أو بعدها).
**النموذج المقترح:** Sonnet (صفحة لوحة بنمط موجود: `/staff` و`/ratings`).
**على dev:** لا migration ولا Edge Function. تنبيه: الدمج بـ `main` ينشر اللوحة تلقائياً لنسخة المعاينة على Cloudflare.
**الحجم:** M.

## الخطوات
1. `apps/admin/src/lib/access.ts`: مسار `/driver-requests` أدمن فقط، تحت "الإعدادات والموظفون" بجانب `/staff`.
2. الصفحة `apps/admin/src/app/(panel)/driver-requests/`:
   - تبويبا "بانتظار الموافقة" (`list_driver_requests('pending')`) و"آخر القرارات" (`'decided'`).
   - الصف: الاسم، الرقم (`tel:` + نسخ)، منذ متى؛ وبالقرارات: الحالة (ومنها منتهية)، من قرر ومتى، الملاحظة.
   - "موافقة": نافذة "اتصلت بالرقم 07… وتأكدت أنه نفس الشخص؟" بخانة إلزامية ← `decide_driver_request(id, true)`.
   - "رفض": نافذة بملاحظة اختيارية ≤ 300 ← `decide_driver_request(id, false, note)`.
   - الأخطاء: `REQUEST_ALREADY_DECIDED` ← تحديث؛ `PHONE_TAKEN` ← "الرقم صار له حساب. رقّيه كسائق من صفحة الموظفين (بعد إعادة ضبط رمزه)".
3. شارة بالقائمة الجانبية بعدد الطلبات المعلّقة (من نفس الدالة، تحديث عند تركيز الصفحة ونقرة الإشعار).
4. فتح إشعار `data.type = 'driver_request'` بالجهاز ← هذه الصفحة.
5. SPEC-admin §2.10 (الصفحة) وجدول الصلاحيات §1؛ RUNBOOK قسم "طلبات السواق": **اتصل بالرقم قبل الموافقة**، الموافقة 7 أيام، تغيير الجهاز قبل الرمز = رفض وطلب جديد، رقم مسجّل كزبون = إعادة ضبط الرمز ثم `set_user_role` سائقاً، نسيان الرمز = `admin-reset-pin`.

## القبول
- موظف يفتح `/driver-requests` بالرابط المباشر ← 403؛ لا يراها بالقائمة.
- الموافقة مستحيلة بلا خانة "اتصلت وتأكدت".
- قرار واحد لكل طلب؛ تبويب القرارات يعرضه مع اسم الأدمن.
- الشارة تساوي عدد المعلّق.
