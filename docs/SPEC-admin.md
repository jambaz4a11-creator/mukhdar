# SPEC-admin: لوحة الأدمن (Next.js)

> `apps/admin`. Next.js (App Router) + Tailwind + `@supabase/ssr`. عربي RTL (`<html dir="rtl" lang="ar">`). تعمل على الحاسوب أولاً وتبقى صالحة على الموبايل.
> القراءة والكتابة بجلسة المستخدم (RLS يحكم). **لا `service_role` بالمتصفح.**

## 1) الدخول والصلاحيات
- دخول بالهاتف + OTP (نفس Supabase Auth).
- `middleware.ts`: لا جلسة ← `/login`. الدور ليس `admin` أو `staff` ← صفحة "غير مصرح".
- القائمة الجانبية تخفي ما لا يخص `staff` (المنتجات، التكاليف، الأرباح، الموظفين، الإعدادات). الحماية الحقيقية في RLS والدوال، والإخفاء للراحة فقط.

| الصفحة | admin | staff |
|---|---|---|
| الطلبات | ✓ | ✓ |
| المخزون (عرض) | ✓ | ✓ |
| المخزون (حركات) | ✓ | ✗ |
| المنتجات والأقسام | ✓ | ✗ |
| العناوين (قطاعات/وحدات/عمارات) | ✓ | ✗ |
| التقارير والأرباح | ✓ | ✗ |
| الموظفون والسائقون | ✓ | ✗ |
| الإعدادات | ✓ | ✗ |

## 2) الصفحات

### 2.1 الطلبات (الصفحة الرئيسية)
- تبويبات بالحالة مع عدادات: جديد (`pending`)، قيد التحضير، جاهز (بانتظار السائق)، بالطريق، مسلّم اليوم، ملغي.
- **Realtime:** اشتراك بـ `INSERT` على `orders` ← صوت تنبيه + إضافة للأعلى. تحديث بـ `UPDATE` للطلبات المعروضة فقط.
- جدول: الرقم، الوقت، الزبون، الوحدة والعمارة، عدد القطع، المجموع، السائق، الحالة. صفحات 50 (keyset).
- فلترة بالتاريخ، الحالة، السائق، والبحث برقم الطلب أو هاتف الزبون.
- **تفاصيل الطلب** (لوحة جانبية):
  - البنود (للتحضير) مع زر **طباعة** (صفحة طباعة بعرض 80mm لطابعة إيصالات).
  - أزرار حسب الحالة والدور: "بدء التحضير"، "جاهز" (يبلّغ كل السائقين النشطين والزبون)، "إلغاء" (يطلب سبباً؛ الموظف حتى `ready`، الأدمن أيضاً من `out_for_delivery`)، "تعيين/تغيير سائق" (من `preparing` أو `ready`؛ قائمة السائقين النشطين من `list_drivers()`، متاحة للموظف والأدمن).
  - سجل الحالات (`order_status_history`) والتقييم إن وُجد.
  - للأدمن فقط: تكلفة البنود والربح.

### 2.2 المنتجات والأقسام (أدمن)
- جدول منتجات: صورة مصغرة، الاسم، القسم، وحدة البيع، سعر البيع (لكل وحدة بيع، مثلاً "السعر / نص كيلو")، **سعر الشراء**، هامش الربح %، الرصيد، نشط، الترتيب.
- إنشاء/تعديل: وحدة البيع **قائمة ثابتة** من `SALE_UNITS` (`نص كيلو`، `باقة`، `حبة`، `علبة`، `قنينة`، `سلة`؛ قيد `products_unit_allowed` بقاعدة البيانات، ووحدة جديدة = migration). السعر لكل وحدة بيع بمضاعفات 250 (تحقق بالنموذج + قيد بقاعدة البيانات)، رفع صورة مع **تصغير بالمتصفح** (800px، WebP، < 200KB) ثم رفع لـ `product-images`.
- تعطيل بدل الحذف (الطلبات القديمة تشير للمنتج).
- تغيير الترتيب بالسحب للأقسام والمنتجات.
- تعديل سريع للسعر من الجدول.
- تنبيه: منتجات بلا سعر شراء.

### 2.3 المخزون
- جدول: المنتج، الرصيد الحالي، آخر حركة. **الرصيد والحركات بوحدة البيع** (للخضار والفواكه: عدد أنصاف الكيلو؛ العرض عبر `formatQuantity`، مثلاً رصيد 20 = "10 كيلو"). تمييز الرصيد المنخفض (أقل من حد قابل للتعديل لكل منتج؛ *مؤجل*، الآن ثابت = 5 وحدات بيع، أي 2.5 كيلو للخضار والفواكه).
- أدمن: "إضافة مشتريات" (`purchase`)، "تالف" (`waste`)، "تسوية جرد" (`adjust`) مع ملاحظة ← `adjust_stock`.
- سجل الحركات لكل منتج، صفحات 50، فلترة بالنوع والتاريخ.

### 2.4 العناوين (أدمن)
- شجرة: قطاعات (`قطاع A`، `قطاع B`) ← وحدات (`A1..A9`، `B1..B8`؛ جدول `subsections`) ← عمارات (`buildings`، 1..100 داخل كل وحدة). إضافة، تعديل الاسم، تعطيل، ترتيب. التسميات بالواجهة: "وحدة" و"عمارة".
- **إضافة عمارات بالجملة لوحدة:** إدخال مدى (مثلاً 1 إلى 100) أو لصق قائمة أرقام، مع معاينة قبل الحفظ وتجاهل المكرر.

### 2.5 التقارير (أدمن)
- من `daily_stats`: اختيار مدى تاريخ (اليوم، أمس، 7 أيام، الشهر، مخصص).
- بطاقات: الطلبات المسلّمة، الملغاة، الإيراد، أجور التوصيل، التكلفة، الربح الإجمالي، متوسط قيمة الطلب.
- رسم بياني يومي للإيراد والربح.
- **أكثر المنتجات مبيعاً** للمدى (استعلام على `order_items` للطلبات المسلّمة بالمدى، حد 20، يعتمد فهرس `orders(status, created_at)`).
- أداء السائقين: عدد الطلبات المسلّمة لكل سائق بالمدى.
- متوسط التقييم وآخر التعليقات.
- تصدير CSV.

### 2.6 الموظفون والسائقون (أدمن)
- قائمة المستخدمين بدور غير `customer`، وبحث بالهاتف لترقية أي حساب.
- تغيير الدور وتعطيل/تفعيل ← `set_user_role`.
- لا يمكن للأدمن تخفيض نفسه.

### 2.7 الإعدادات (أدمن)
- أجرة التوصيل (مضاعفات 250)، الحد الأدنى للطلب (مضاعفات 250)، حد الطلبات المفتوحة للزبون (افتراضي 3)، فتح/غلق المتجر + رسالة الإغلاق.
- حالة الإشعارات: عدد الإشعارات غير المرسلة الأقدم من 5 دقائق (تنبيه إن كان > 0).

## 3) الأداء
- كل الجداول بصفحات (50) وفلترة على الخادم. لا تحميل لكل الطلبات.
- التقارير من `daily_stats`؛ فقط "أكثر المنتجات مبيعاً" و"أداء السائقين" استعلامات مباشرة محدودة بمدى التاريخ.
- Server Components للقراءة الأولية، وTanStack Query للتحديث.

## 4) الاختبارات
- **Playwright (ضد Supabase محلي + seed):**
  - أدمن: دخول، إنشاء منتج بصورة، تعديل سعر، إضافة مخزون، بدء تحضير طلب، تعيين سائق، رؤية التقرير.
  - staff: لا يرى صفحات الأدمن، ولا يصل لها بالرابط المباشر، ويقدر يحضّر ويلغي.
  - زبون يحاول فتح اللوحة ← "غير مصرح".
- **وحدة:** تحقق السعر (مضاعف 250)، تصغير الصورة، تحليل مدى العمارات.

## افتراضات
1. اللوحة على Vercel (الخطة المجانية تكفي للبداية)، مع نطاق فرعي مثل `admin.<domain>`.
2. صفحات سياسة الخصوصية والشروط وحذف الحساب (للويب، مطلوبة من Google) ضمن نفس مشروع Next.js كصفحات عامة.
3. الطباعة عبر نافذة طباعة المتصفح (لا تكامل مباشر مع طابعة).
4. حد الرصيد المنخفض ثابت (5) بالمرحلة الأولى.
5. لا سجل تدقيق لتعديلات المنتجات بالمرحلة الأولى (فقط حركات المخزون وحالات الطلب مسجلة).
6. تعديل بنود طلب قائم غير مدعوم: الحل إلغاء الطلب وطلب جديد من الزبون.
